# v2_validation — intermediate, provenance only

Introduces an 80/20 train/validation split intended to eliminate the
hyperparameter-leakage risk present in v1 (τ tuned and tested on the same
data). Used to generate the review version's validation sweep (paper Table 6;
see `docs/REPRODUCING_TABLES.md`).

**Update:** the original split implementation in this version was not
actually stable across runs, despite using a fixed RNG seed — see
[`docs/FIXES.md`](../../docs/FIXES.md) #20. `list({...})` on a Python `set`
has per-process-randomized iteration order, so the seeded shuffle's *input*
order still varied run to run, silently producing a different val/test
partition on every invocation. This was caught by re-running an identical
configuration twice and observing validation MRR swing by up to 0.31 (n=7)
with no other variable changed. **Fixed** as of #20 (`sorted()` instead of
a bare set comprehension) — the split is now genuinely reproducible.
Fix #19 (device mismatch, same root cause as #14) is also applied here.

If you have numbers generated by this file *before* those two fixes,
treat them as provenance only, not as a reproducible reference — re-run
after pulling the fix if they're load-bearing for any claim.

Superseded by `../v3_patched/` for all other reported numbers, which fixes
several additional bugs found after this version (see `docs/FIXES.md`
#1, #3, #4, #5, #8-#11 — none of which are present in this version).
v3_patched does not implement a val/test split at all (evaluates on the
full set directly), so it was never exposed to #19 or #20.
